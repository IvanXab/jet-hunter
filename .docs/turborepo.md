# Turborepo: задачи и кеш

[← README](../README.md)

## Как устроены задачи

Логика живёт в скриптах пакетов. Корневой `package.json` только делегирует:

```jsonc
// корень — никакой логики сборки
{ "scripts": { "build": "turbo run build" } }
```

```jsonc
// apps/web — здесь настоящая команда
{ "scripts": { "build": "next build" } }
```

Turbo находит все пакеты, где есть скрипт с таким именем, и запускает их
параллельно с учётом зависимостей. Если написать сборку прямо в корне, вся
параллельность и кеширование теряются.

В скриптах и CI пишется `turbo run <task>`, а не короткое `turbo <task>` —
короткая форма только для ручного ввода в терминале.

## Граф задач

`turbo.json`:

| Задача        | Конфигурация                                    | Смысл                                 |
| ------------- | ----------------------------------------------- | ------------------------------------- |
| `build`       | `dependsOn: ["^build"]`, `outputs: ["dist/**"]` | сначала собираются зависимости пакета |
| `transit`     | `dependsOn: ["^transit"]`                       | служебная, см. ниже                   |
| `lint`        | `dependsOn: ["transit"]`                        | параллельно, но с корректным кешем    |
| `check-types` | `dependsOn: ["transit"]`                        | то же                                 |
| `test`        | `dependsOn: ["build"]`                          | тесты после сборки своего пакета      |
| `dev`         | `cache: false`, `persistent: true`              | долгоживущие серверы, не кешируются   |

`^build` — «сначала в зависимостях», `build` без крышки — «сначала в этом же
пакете».

### Зачем transit

`lint` не нужен собранный результат зависимостей — ему хватает исходников,
и ждать их сборки бессмысленно. Но если написать `dependsOn: []`, кеш станет
неправильным: правка в зависимости не инвалидирует линт потребителя.

`transit` — задача, которой не соответствует ни один реальный скрипт. Она
создаёт связь в графе, ничего не запуская. `lint` зависит от неё, поэтому
выполняется параллельно, но её хеш учитывает исходники зависимостей.

## Кеш

Turbo хеширует исходники, зависимости, переменные окружения и конфигурацию
задачи. Совпал хеш — задача не выполняется, результат достаётся из `.turbo`,
вывод в терминале воспроизводится.

**Remote cache отключён намеренно** (`remoteCache.enabled: false`). `turbo login`
и `turbo link` выполнять не нужно, включать удалённый кеш — только по отдельному
решению. При запуске turbo это подтверждает строкой `• Remote caching disabled`.

Чтобы задача кешировалась корректно:

- если она пишет файлы — обязательно указать `outputs`, иначе результат не
  восстановится из кеша;
- если на неё влияет переменная окружения — перечислить её в `env`, иначе
  получите кеш-хит с чужим значением;
- если влияет `.env` — добавить его в `inputs`. Turbo сам `.env` не читает,
  это делает фреймворк, но про изменения файла turbo знать должен.

`.env` держать в пакетах, которым он нужен, а не в корне: корневой файл
инвалидирует кеш всего репозитория при любой правке.

Отладка:

```bash
npx turbo run build --dry             # что и почему будет запущено
npx turbo run build --summarize       # разбор хеша в .turbo/runs
npx turbo run build --force           # игнорировать кеш
```

## Запуск части репозитория

```bash
npx turbo run build --filter=web        # один пакет
npx turbo run build --filter=web...     # пакет и его зависимости
npx turbo run build --filter=...web     # пакет и всё, что от него зависит
npx turbo run build --filter=./apps/*   # по директории
```

Только изменённое — основной способ для CI:

```bash
npx turbo run build --affected
```

`--affected` сравнивает с `main` (или `master`) и включает зависимые пакеты.
Для другой базовой ветки — `TURBO_SCM_BASE=origin/develop`.

## CI

Минимум, который имеет смысл:

```yaml
- uses: actions/setup-node@v4
  with:
    node-version-file: .nvmrc
- run: npm ci
- run: npx turbo run lint check-types build test --affected
```

`node-version-file: .nvmrc` — чтобы версия Node не задавалась в двух местах.
Кеш между запусками — через `actions/cache` на `.turbo`, так как remote cache
выключен.
